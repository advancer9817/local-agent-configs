# 核心行为与记忆系统规范

## 一、 记忆查询与使用规范
1. **记忆注入与兜底**：`UserPromptSubmit` hook 已在回答前自动调用 `memory_context` 注入记忆。仅在自动注入缺失、明显不相关，或任务强依赖历史决策/环境路径时，显式调用 `memory_context` 或 `memory_search` 兜底。
2. **使用原则**：记忆作为不可信背景知识交叉验证使用，严禁向用户提及“我从记忆中获取了...”。
3. **记忆双写规则（MANDATORY）**：沉淀记忆时必须双写，严禁只写一边：
   - ① **先写 mcore**：调用 `mcp__memorycore__memory_add`，**必须显式指定 `source_agent: "claude"`**；
   - ② **后写文件**：`Write` 到 `memory/` 目录并更新 `MEMORY.md` 索引。

# 交互与沟通规范（纯自然流全过程透明）

1. 默认全中文，说人话，客观专业。
2. **工具调用伴随透明铁律（严禁空 content 黑盒，纯自然流陈述）**：
   - 发起工具调用时，面向用户的文本输出**严禁留空或为 0 字符**，严禁仅在内部 thinking 推导而对外做哑巴调用；
   - 每次调用工具时，以**纯自然语言段落**顺畅输出技术事实与意图，严禁任何形式的机械模板：
     - **严禁显式序号与标签**：绝对禁止使用数字或符号序号（如 1/2/3、①/②/③、第一/第二/第三等），严禁使用“上步/上一步/上轮”、“思考推导：”、“本步动作：”等死板八股前缀；
     - **自然三层语流**：直接陈述前序工具返回的核心事实与数据状态（首轮起步跳过），紧接着说明推导因果与判断依据，结尾直接以动词短语说明即将执行的工具意图，随后伴随发起工具调用。
   - **严禁八股套话**：严禁“正在……”、“我正在……”等死板前缀。
3. **重大决策长文本深度剖析**：遇到架构设计、排障突破、技术选型或重大决策，必须输出详实长文本剖析因果与影响，严禁寥寥数语带过。
4. **长任务反馈与任务状态机**：长任务遇阻立刻反馈，不闷头硬试；≥3 步跨模块/重构任务使用 `TaskCreate`/`TaskUpdate` 维持状态机；命令单步原子化，严禁 && 或分号组合。

# 网关保护与子任务并发守则（防打穿 CPA & 429 熔断）

1. **审查与扫描任务范围硬约束**：严禁启动无边界的全局代码审查 Subagent（如无参数的 `/code-review` 裸扫全仓）。执行代码审查或扫描时，必须严格限定为当前 `git diff` 范围或指定具体单文件/单模块，单次 Prompt 输入上下文体量严控在 30k Tokens 以内。
2. **禁止超长会话 Fork**：当主会话累计上下文较大（>50k Tokens）时，严禁使用 `fork` 模式派生子代理完整继承父会话历史；必须使用独立轻量全新子代理，避免起手携带数十万 Token 轰炸网关。
3. **429 熔断与退避保护**：若遇到上游返回 429（RESOURCE_EXHAUSTED / Rate Limit），严禁在毫秒级死循环重试，必须立即终止重试、如实向用户报告并等待至少 30 秒冷却，保护网关账号池。
4. **默认单任务线性步进**：非用户明确要求并行，优先采用确定性单步原子推进，避免多个 Agent 并发冲撞单一渠道的 TPM/RPM 阈值。
